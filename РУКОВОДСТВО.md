# Руководство по шаблону сайта-визитки

Как быстро и без ошибок собрать новый сайт из этого шаблона.

> **Прочитать целиком до первой правки.** Шаблон — не статичная вёрстка, а
> Webflow-экспорт с самописным движком анимаций. Половина «странных» багов
> возникает из-за правок, которые в обычной вёрстке безопасны.

## Часть I. Как это устроено

### 1.1. Файлы

```
index.html                     основной файл
page.html                      ДУБЛЬ index.html (держать байт-в-байт одинаковыми)
css/nesh-staging...min.css     стили Webflow (97 КБ) — НЕ РЕДАКТИРОВАТЬ
js/f1-assets-script.js         движок анимаций (112 КБ) — правки точечные, см. 1.3
js/*.min.js                    GSAP, ScrollTrigger, SplitText, Lenis, Swiper
fonts/                         PP Neue Montreal (кириллица есть) + Tr 3 A (латиница!)
images/                        картинки
РУКОВОДСТВО.md                 этот файл
```

Все кастомные CSS-правки живут в одном `<style>`-блоке внутри `<body>`
(`ADVOKAT CUSTOM`) — внешний CSS не трогаем никогда, чтобы шаблон
оставался переиспользуемым.

### 1.2. Главное правило: движок пишет inline-стили

`f1-assets-script.js` при загрузке **измеряет** элементы
(`getBoundingClientRect`, `getComputedStyle`) и затем **записывает им
inline-стили** через GSAP: `width`, `height`, `transform`, `position`,
`top`, `left`, `opacity`.

> **CSS-правило с `!important` побеждает inline-стиль.** GSAP пишет
> `element.style.width = '131px'` без `!important`. Значит правило
> `.nav-button{width:auto !important}` **запрещает движку менять ширину** —
> анимация ломается молча, без ошибок в консоли.

**Запрещено** трогать `width` / `height` / `display` / `overflow` /
`transform` (и особенно с `!important`) у элементов из таблицы 1.4.

**Разрешено** менять у них: `color`, `background-color`, `font-size`,
`letter-spacing`, `margin`, `padding`, `border-radius`. Этих свойств движок
не касается — в коде есть явные `delete fromVars.fontSize` и `delete
fromVars.color`.

| `StyleEngine` | обработка `data-tl-*` атрибутов |
| `HorizontalScroll` | горизонтальная лента кейсов |
| `MobileMenu` | гамбургер-меню |
| `MagneticPositions` | привязка карточек к тексту (`data-connect`, см. 1.5) |
| `CardInteractions` | ховеры карточек |
| `ProfileImage` | фото в hero |
| `SwiperInit` | карусель отзывов |
| `LenisInit` | плавный скролл всей страницы |
| `TextReveal` | посимвольная анимация текста в «Преимуществах» |
| `ImageTrail` | шлейф картинок в футер-логотипе (**отключён**, см. 3.9) |
| `Clipboard` | копирование e-mail |

### 1.4. Система «призраков» (GhostEngine)

Элемент в шапке плавно «перелетает» на своё место в hero при скролле.
Элементы ходят **парами**:

| «Реальный» (в шапке) | «Призрак» (в hero, невидим) | Тип анимации |
|---|---|---|
| `.nav-logo-item .nesh-logo` | `.nesh-logo-ghost` | logo |
| `.nav-button` | `.hero-cta-button` | logo |
| `.nav-button-secondary` | `.hero-button` | logo |
| `.hero-navigation-link[data-link-id]` | `.hero-link-ghost[data-link-id]` | link |
| `.nav-webflow-bg` | `.hero-card-2-bg` | background |
| `.nav-webflow-icon` | `.hero-webflow-icon` | icon_center |
| `.nav-webflow-text` | `.hero-webflow-projects-text` | text_font |
| `.nav-experience-bg` | `.experience-bg` | background |
| `.nav-experience-numb` | `.experience-number` | icon_center |
| `.nav-experience-text` | `.experience-text` | text_font |

Источник: `GhostEngine.createAll()`.

**Правила для пар:**

1. **Меняешь контент в одном — меняй и в парном.** Иначе на десктопе видно
   одно значение, а на мобильном другое.
2. **Не меняй тип тега.** Типы `icon_center` и `background` считают
   `scaleX = ширина_призрака / ширина_реального`. Если призрак был `<svg>`,
   а стал `<p>` — пропорции разъедутся, элемент растянет.
3. **Сохраняй `data-flip-*` и `data-tl-*`** — движок читает настройки с них.
4. **Ниже 768px GhostEngine выключен** (`if (window.innerWidth < 768) return`).
   Значит мобильные баги — это почти всегда чистый CSS, а не JS.

### 1.5. Система привязки карточек (MagneticPositions)

В секции «Преимущества» карточки физически лежат в конце DOM, а визуально
плавают внутри текста. Связь — через атрибуты:

```html
<!-- якорь внутри текста: резервирует место -->
<span data-connect="w" class="span" style="white-space:nowrap">&nbsp;&nbsp;&nbsp;</span>

<!-- карточка: цепляется к якорю -->
<div data-connect="w" data-connect-mobile="w-mobile"
     data-origin="center center" data-anchor-pos="center center"
     data-offset="0, 16%" class="capa-card">
```

| Атрибут | Что делает |
|---|---|
| `data-connect` | id связи с якорем (десктоп) |
| `data-connect-mobile` | то же для <768px (у мобильного текста свои якоря) |
| `data-origin` | какая точка карточки цепляется |
| `data-anchor-pos` | к какой точке якоря |
| `data-offset` | сдвиг `X, Y` (px / % / vw) — **безопасный способ подвинуть** |

**Важно:** якорь и карточка ищутся так — `[data-connect="id"]:not([data-origin])`
это якорь, с `data-origin` — карточка. Ширина якоря должна примерно
соответствовать ширине карточки.

### 1.6. Брейкпоинты и цвета

Брейкпоинты Webflow: **991 / 767 / 479**. Плюс `clamp()` для плавных размеров.

```css
:root{
  --yellow:#ffff23;  --black:black;  --white:white;
  --tra:"Tr 3 A",Arial,sans-serif;
}
```

Фон страницы `#d5cfbe` задан на `body` во внешнем CSS.

**Смена фирменного цвета** — жёлтый живёт в трёх местах:
- `var(--yellow)` в CSS — 22 использования (перекрывается переопределением `:root`);
- хардкод `#ffff23` в CSS — 10 штук;
- **хардкод в HTML — 48 штук** (`fill="#FFFF23"` и `#FDF822` внутри SVG-иконок).

То есть просто переопределить переменную недостаточно — нужен ещё поиск-замена
по HTML.

## Часть III. Пошаговая сборка нового сайта

### Шаг 0. Подготовка

```bash
cp -r lawyer-site новый-клиент
```

Добавить запись в `.claude/launch.json` (свой порт) — сайты работают
параллельно, удобно сравнивать.

### Шаг 1. Собрать контент от клиента

Отправить анкету (`questionnaire.docx` — шаблон в этом проекте). Минимум:
имя, специализация, город, телефон/почта/мессенджеры, реквизиты, 4 вехи
карьеры, 6 услуг с пунктами, 6 кейсов, 3 отзыва, 6 FAQ, 2 цифры для
счётчиков, фото.

**Не выдумывать отзывы и кейсы.** Нет реальных — убрать блок целиком.

### Шаг 2. Текст: сквозная замена

Работать Node-скриптом с `.split().join()`, а не Edit — HTML в одну строку.

```bash
node -e "
const fs=require('fs');
const pairs=[['Старый текст','Новый текст']];
['index.html','page.html'].forEach(f=>{
  let h=fs.readFileSync(f,'utf8');
  pairs.forEach(([a,b],i)=>{
    const n=h.split(a).length-1;
    if(n!==1) console.log('WARN['+i+'] совпадений:', n);  // ← всегда проверять
    h=h.split(a).join(b);
  });
  fs.writeFileSync(f,h);
});"
```

**Всегда проверять число совпадений.** Один и тот же текст часто есть в
нескольких местах (см. 3.1).

### Шаг 3. Логотип (4 места!)

Буквы лого — **векторные контуры, не текст**. Обычная замена не сработает.

Места: `.nesh-logo-preload-svg` (прелоадер), `.nesh-logo-ghost` (гигантский
фоновый), `.nesh-logo-svg` (в панели), `#nesh-clip` в футере (`clipPath`).

Готовый рецепт — вытащить контуры из шрифта:

```bash
pip install fonttools brotli
python -c "
from fontTools.ttLib import TTFont
from fontTools.pens.svgPathPen import SVGPathPen
from fontTools.pens.boundsPen import BoundsPen
f = TTFont(r'fonts/ppneuemontreal-bold.woff2')   # кириллица есть
gs = f.getGlyphSet(); cmap = f.getBestCmap()
text = 'ФАМИЛИЯ'
x=0; parts=[]
for ch in text:
    g = gs[cmap[ord(ch)]]
    pen = SVGPathPen(gs); g.draw(pen)
    bp = BoundsPen(gs); g.draw(bp)
    parts.append({'d':pen.getCommands(),'adv':f['hmtx'][cmap[ord(ch)]][0],'x':x,'b':bp.bounds})
    x += parts[-1]['adv']
print('width:', x)
"
```

Затем сдвинуть каждый контур на его `x` и **отразить по Y**
(`y_new = cap_top - y`), потому что в шрифте ось Y направлена вверх, а в
SVG — вниз. Итоговый `viewBox="0 0 {width} {height}"`.

> **Шрифт `Tr 3 A` кириллицу НЕ содержит** — только `ppneuemontreal-*`.
> Проверять перед использованием.

### Шаг 4. Фото

| Элемент | Виден | CSS | Нужен файл |
|---|---|---|---|
| `.hero-profile-img` | ≥768px | `object-fit:contain` в `100vw×100vh` | **исходник как есть**, без полей |
| `.mobile-hero-image` | <768px | обёртка фикс. высоты ~760px | `height:100%; object-fit:cover` + `object-position` |
| `.about-card-img`, `.cta_img` | везде | круглые бейджи ~128px | круглый аватар с фоном `#cecdbb` |
| `.client-img` | отзывы | круглые фото | фото людей |

Круглый аватар (фон вшивается в файл, как в оригинале):

```python
from PIL import Image, ImageDraw
SIZE, BG = 256, (206,205,187,255)
src = Image.open('photo.png').convert('RGBA')
crop = src.crop((L,T,R,B)).resize((SIZE,SIZE), Image.LANCZOS)
canvas = Image.new('RGBA',(SIZE,SIZE),BG); canvas.alpha_composite(crop)
mask = Image.new('L',(SIZE*4,SIZE*4),0)
ImageDraw.Draw(mask).ellipse((0,0,SIZE*4,SIZE*4),fill=255)
out = Image.new('RGBA',(SIZE,SIZE),(0,0,0,0))
out.paste(canvas,(0,0),mask.resize((SIZE,SIZE),Image.LANCZOS))
out.save('avatar.png')
```

**Не добавлять прозрачные поля в файл** ради пропорций — при
`object-fit:contain` фото визуально уменьшится. Пропорции решаются CSS.

### Шаг 6. Иконки

Иконки — инлайновые SVG с `fill="currentColor"`. Стиль: плоские
геометричные фигуры без градиентов. Рисовать полигонами в `viewBox`
исходной иконки, чтобы не ломать вёрстку.

**Проверять размер после замены** — CSS-класс может задавать ширину под
старую иконку (`.gsap-icon` был под широкий логотип → пришлось
`style="width:1.9rem"`).

## Часть IV. Каталог граблей

Всё ниже — реальные баги из сборки первого сайта. Каждый стоил времени.

### 4.1. Один текст в нескольких местах

«Получить консультацию» существовал в **4** экземплярах: `.hero-cta-button`
(призрак), `.nav-button` (шапка), `.nav-button` в мобильном меню,
`.cta-button` (нижний блок). Правка одного не меняла видимый.

**Правило:** перед заменой посчитать вхождения; после — проверить, что
изменилось именно видимое (через `getComputedStyle`/`getBoundingClientRect`,
а не на глаз).

### 4.2. `!important` ломает анимацию молча

Симптом: кнопки раздваиваются, появляются сразу на загрузке, съезжает
мобильная вёрстка. Причина: `width:auto !important` на `.nav-button`
запрещал GSAP менять ширину.

Отдельно: `.hero-buttons-wrap{display:flex !important}` без медиа-запроса
ломал мобильную раскладку (там по замыслу `display:none`).

**Правило:** нет `!important` на геометрию элементов движка. Если текст не
влезает — сначала проверить `el.scrollWidth > el.clientWidth`, часто
переполнения нет вовсе; если есть — **сокращать текст**, а не ломать CSS.

### 4.3. Рассинхрон пары ghost↔real

`.experience-number` заменили на `<p>30</p>`, парный `.nav-experience-numb`
остался `<svg>` с «7+». Тип `icon_center` считает масштаб по отношению
размеров — цифра растянулась в «Ъ0».

**Правило:** правки только парами, тип тега не менять.

### 4.4. `<span>` внутри `.hero-heading`

Заголовок режется `SplitText` на строки. Вставленный
`<span style="display:inline-block">` ломал разбиение.

**Правило:** внутри `.hero-heading` только текст и `<br>`.

### 4.5. Перенос строки внутри якоря (`data-connect`)

У якорей вида `<span>&nbsp; &nbsp; &nbsp;</span>` между `&nbsp;` стояли
**обычные пробелы**. По ним браузер переносил строку, якорь разрывался на
две строки, его прямоугольник раздувался (992×188 вместо 140×100) —
и карточка улетала в случайное место.

**Правило:** всем якорям `data-connect` ставить `style="white-space:nowrap"`.
Эта же уязвимость есть в оригинале heynesh.com — просто там не проявилась.

### 4.6. Правка текста двигает все карточки следом

Попытка «раскидать» иконки добавлением `&nbsp;` между словами сдвинула
переносы по всему абзацу: было 2 конфликта, стало 11.

**Правило:** для сдвига карточки использовать `data-offset`, а не правку
текста. Если нужно больше строк — удлинять текст осмысленными словами,
проверяя после каждого шага.

### 4.7. Ловушка порядка правил в исходном CSS

```css
@media (max-width:479px){ .hero-buttons-wrap{display:flex} }  /* раньше в файле */
@media (max-width:767px){ .hero-buttons-wrap{display:none} }  /* позже в файле */
```

При ≤479px истинны **оба** условия, побеждает **последнее в файле**, а не
более узкое. Это намеренное поведение шаблона, не баг.

### 4.8. Lenis перехватывает колесо мыши

Карусель отзывов не листалась трекпадом. Плавный скролл страницы (Lenis)
забирал события `wheel` себе.

**Решение:** `data-lenis-prevent` на контейнер `.swiper` + модуль
`mousewheel` в конфиге Swiper с **`forceToAxis: false`** (при `true`
горизонтальная карусель требует именно горизонтального жеста и обычная
вертикальная прокрутка не работает).

### 4.9. Чужой контент, который легко забыть

- **ImageTrail** в футер-логотипе подтягивал фото портфолио Ненада с
  внешнего CDN при наведении. Отключено удалением цели
  `<g id="image-trail-group">` — модуль не находит селектор и тихо не
  стартует.
- **`.client-img` в отзывах** — до сих пор фото реальных клиентов Ненада
  (`Danette Beal.avif`, `Klemen Vute.avif`, `petar_s.jpeg`). **Заменить
  обязательно.**
- **`.work-image`** — скриншоты чужих проектов (`Frame *.avif`).
- Атрибуты `data-wf-domain="heynesh.com"`, `data-wf-page`, `data-wf-site` —
  безобидные следы экспорта, но лучше почистить.

### 4.10. Двойная инициализация движка

Повторный `AnimationEngine.init()` без перезагрузки дублирует ScrollTrigger-пины
и ломает высоту документа (`Animation engine already initialized` в консоли).

**Правило:** после правок — полная перезагрузка страницы, `init()` максимум
один раз.

### 4.11. Особенности среды разработки

- Вкладка инструмента может считаться скрытой (`document.hidden`), тогда
  `requestAnimationFrame` не идёт и анимации не стартуют сами → вызвать
  `window.AnimationEngine.init()` вручную.
- Скриншот иногда возвращает пустой/устаревший кадр. **Доверять
  `getBoundingClientRect`/`getComputedStyle`, а не картинке.**
- `loading="lazy"` в этой среде может не срабатывать — картинка «не
  загружена», хотя файл валиден.

## Часть V. Как добавлять новые блоки

### 5.1. Дублирование карточки

Самый надёжный способ — скопировать существующую и заменить содержимое.
Границы блока определять **подсчётом вложенности**, а не регуляркой:

```javascript
function extractBlock(html, marker){          // marker: 'class="service-card"'
  const i = html.indexOf(marker);
  const start = html.lastIndexOf('<div', i);
  let depth = 1, p = html.indexOf('>', start) + 1;
  while (depth > 0) {
    const o = html.indexOf('<div', p), c = html.indexOf('</div>', p);
    if (c < o || o === -1) { depth--; p = c + 6; }
    else { depth++; p = html.indexOf('>', o) + 1; }
  }
  return { start, end: p, html: html.slice(start, p) };
}
```

После вставки — **обязательно** проверить баланс `<div>`. В прошлый раз
регулярка добавила по лишнему `</div>` в 6 карточек; ловится скриптом,
который считает глубину и сообщает, где она ушла в минус.

### 5.2. Что поправить в копии

- **Уникальные `id`** — Webflow генерирует `w-node-...`, `w-dropdown-N`.
  Для FAQ важны связки `id="w-dropdown-toggle-N"` ↔
  `aria-controls="w-dropdown-list-N"`.
- **`data-tl-start`/`data-tl-end`** — задают, когда блок появляется при
  скролле. У соседних карточек значения разные (`-45%`, `-4%`, `20%`,
  `58%`) — при копировании выставить своё, иначе анимация синхронная.
- **`data-connect`** — для карточек-привязок нужен новый id и **новый
  якорь** в тексте (и в мобильном тексте тоже).

### 5.3. Смена числа карточек в сетке

`.service-wrap` изначально `display:flex` в один ряд с фиксированной
шириной карточек `22.22vw` — 6 карточек не помещались. Переведено в grid:

```css
@media (min-width: 768px) {
  .service-wrap { display: grid; grid-template-columns: repeat(3, 1fr); }
  .service-card { width: 100%; }
}
```

Для выравнивания разновысоких блоков внутри карточки:
`.service-card{height:100%}` + `.service-bottom-content{margin-top:auto}`
(+ `min-height` тексту, если нужно ровнять и верх).

### 5.4. Целая новая секция

1. Скопировать `<section>` с похожей структурой.
2. Дать новый `id`, обновить `data-tl-trigger` внутри на него.
3. Добавить пункт меню — **два элемента**: `.hero-navigation-link`
   (в `.nav-menu-item`) и парный `.hero-link-ghost` с тем же `data-link-id`.
4. Проверить порядок секций в DOM (влияет на скролл-триггеры).
